# 人員増要求シューティング：試作メモ

このメモでは、会話で採用された設計と、動作を確かめるための試作用の設定を分ける。試作用の数値・表現を正式設定として扱わない。コードから読み取った実装値と、動作を確認した結果は別欄に記録し、確認範囲を区別する。

## 採用済みの設計

| 設計 | 採用した内容 |
|---|---|
| ① | 中心の面白さは、反論を攻略して要求を通す達成感。 |
| ② | 根拠資料を回収して反論バリアを弱め、射撃で突破してから要求書を通す。 |
| ③ | 資料は回収するまで残る。攻撃の隙を見極めて取りに行く。 |
| ④ | 決裁窓へ位置を合わせ、提出ボタンを自分で押して要求書を通す。 |
| ⑤ | 提出に失敗しても、資料回収とバリア突破の成果を保持し、提出だけ再挑戦する。 |
| ⑥ | 一つの要求を3段階で進め、最後に採択する。途中の成功は交渉の前進として扱う。 |
| ⑦ | 最初に通す要求は「人員増」。 |
| ⑧ | 被弾によるゲームオーバーは設けず、被弾回数をクリア評価へ反映する。 |
| ⑨ | 制限時間は設けない。経過時間は結果に示す参考記録とし、評価に使わない。 |
| ⑩ | 初期版からPC・スマホの両方に対応する。 |
| ⑪ | スマホでは盤面の下の専用操作帯を使い、指の左右移動量に応じて自機を移動させる。 |
| ⑫ | 理事は冷静に条件を問う経営者型とする。コミカルな動揺や狼狽を中心とする人物像は採用しない。 |
| ⑬ | 最後の採択では、要求書への採択印を中心に見せる。その後に被弾評価と参考時間を示す。 |
| ⑭ | 主要な画風はシンプルな2Dイラスト。具体的な色や人物属性までは確定していない。 |
| ⑮ | 第1段階で、移動・資料回収・反論突破・手動提出を順に体験するガイドを用意する。説明中は弾・被弾判定・時間記録を停止し、スキップも可能にする。 |
| ⑯ | 開始時に「やさしい・ふつう・むずかしい」の3種類から難易度を選べるようにする。 |
| ⑰ | 最初の試作では、全3段階を採択・結果表示まで通して遊べるようにし、3難易度も選択できるようにする。 |

## 試作のための仮置き事項

以下は、採用済みの体験を実装して確かめるための仮設定。距離や速度は、画面の実ピクセルではなく480×600の論理座標を基準とする。

| 項目 | 試作で想定する扱い | 実装値・照合状況 |
|---|---|---|
| 基本移動・通常射撃 | 左右移動と自動射撃を土台にする。移動速度や表示領域の大きさは調整対象。 | 論理領域480×600、自機Y＝530、移動上限260/秒、左右端の余白22。通常弾は0.18秒間隔、速度560/秒。 |
| PC操作 | 左右移動、手動提出、一時停止のキーを用意する。 | 移動は左右キーまたはA・D、提出はSpace、一時停止はEsc。 |
| スマホの入力変換 | 接触開始位置へ自機を飛ばさず、指の移動量を相対移動に変換する。 | 指の移動量に「480÷盤面の表示幅」を掛けて目標位置を更新し、最大260/秒で追従。指を離すと目標位置を解除する実装。 |
| 資料回収前の射撃 | 回収前の通常弾はバリアに効かず、資料回収を弱体化の条件にする案。 | `barrier.weak`が真の場合だけ耐久値を減らす。資料回収時に真にする。 |
| 資料数 | 各段階に1点の資料を置く案。回収済みの成果はその段階の提出成功まで保持する。 | 各段階のプレイ時間3.2秒で出現。Y＝530、X＝350／125／350。消失期限なし。 |
| バリア耐久 | 資料回収後、通常射撃で崩すための耐久値を置く。 | 初期耐久24、Y＝170。弱体化後、到達した通常弾1発につき1減少。 |
| 提出窓 | 固定位置に置き、バリア突破後は閉じない案。提出のやり直しで反論攻略へ戻さない。 | Y＝110、幅96、X＝240／160／320。要求書の速度460/秒。外れた場合は提出待ちへ戻る。 |
| 当たり判定 | 自機、攻撃、資料、要求書、提出窓の判定を設定する。 | 自機半径11、敵弾半径6の円同士。資料はX方向の距離28以内で回収。提出は窓への到達時に要求書中心Xが窓中心±48以内なら成功。 |
| 被弾後の無敵 | 同じ攻撃との連続接触などで被弾回数が不自然に増えないようにする案。 | 被弾後1秒。接触した敵弾は除去する。 |
| 被弾評価 | 被弾回数からクリア評価を求める。経過時間は評価に加えない。 | S＝0回、A＝1〜4回、B＝5〜12回、C＝13回以上。難易度による閾値変更なし。 |
| 難易度差 | 弾速、発射間隔などに違いを設ける。 | 下表参照。各難易度のバランスは未実機確認。 |
| 段階の内容 | 必要性、費用、実施方法の順に交渉する案。具体的な台詞・資料名は試作用の表現とする。 | 「業務量・配置資料」「費用・効果資料」「採用・配置計画」を各段階に配置。 |
| 攻撃パターン | 段階ごとに反論の読み方を変える案。 | 第1段階は列を予告した直進弾、第2段階は攻撃周期開始時の自機位置を狙う発射後非追尾弾、第3段階は攻撃周期ごとに左右交互の直進弾。弾が途切れる区間は自動テストで確認。利用者にとっての難易度は未評価。 |
| 結果への難易度表示 | 選択した難易度を結果に添える案。 | 結果の見出しに難易度を表示する実装。得点倍率は設けていない。 |
| 一時停止と復帰 | ガイド以外の中断でも、入力を解除し、進行・被弾判定・時間記録を止め、再開時に状態を保持する案。 | Esc停止、遊び方の表示から復帰、別の表示枠へフォーカスを移した際の自動停止をCloud Chromeで確認。画面回転そのものは未確認。 |
| 配色・人物の外見 | シンプルな2D表現と冷静な人物像を守る。具体的な色、服装、年齢、性別、造形は試作用であり、正式設定ではない。 | UI背景は濃い緑青`#102d33`、アクセントはミント`#8be3cb`、採択印は朱色`#c54b46`。理事は眼鏡・スーツ姿の仮の2D造形。 |

### 難易度の仮値

| 難易度 | 弾速（論理座標/秒） | 予告時間（秒） | 連続発射回数 | 連続発射の間隔（秒） | 追加の待機時間（秒） |
|---|---:|---:|---:|---:|---:|
| やさしい | 135 | 1.1 | 2 | 0.28 | 2.1 |
| ふつう | 175 | 0.85 | 3 | 0.22 | 1.65 |
| むずかしい | 225 | 0.65 | 4 | 0.18 | 1.25 |

「連続発射回数」は弾の総数ではない。列状の攻撃では、1回の発射で複数の列へ弾を出す。攻撃周期は、予告時間、連続発射にかかる時間、`600÷弾速`の通過待ち、追加の待機時間を足して設定している。各段階の最初の攻撃開始前には1.4秒の待機を置く。

「約3分」は従来の企画上の目安であり、強制終了する上限ではない。人数、費用、改善効果などの具体的な値を、実在する病院の事実として補完しない。

### 修正した入力の問題

通常の資料回収による`collect → break`の切り替わりで、移動キーとドラッグまで解除される問題を修正した。`syncPhase()`では提出操作の準備状態だけを解除し、`trySubmit()`でも移動入力を保持する。モーダルや一時停止に必要な入力リセットは維持している。

修正コードを読み戻して確認した。ブラウザでも、資料回収をまたぐ1回の操作帯ドラッグが継続し、回収後も指に相当するポインタの動きへ追従することを確認した。これはCloud Chrome上の確認であり、スマホの実タッチ機器での確認ではない。

## 実装時に注意する境界

- 提出失敗では資料・突破の成果を保持し、段階が進んだら次の段階の資料・バリアを用意する。新規プレイでは全体の進捗を初期化する。
- 「発射が止まる」と「残弾が通過して回収できる」は別に確認する。
- ガイドを閉じた入力、移動用の接触、キーの自動反復を、意図しない提出に流用しない。
- 過去の仮案にあった残機切れ、時間切れ、必殺技などを、今回の採用済み条件として追加しない。
- 仮の閾値や表現は、確認できた実装値と合わせて更新し、正式な採用事項とは分ける。

## 照合状況

上記の仮値と処理は、`dist/engine.js`、`dist/app.js`、`dist/styles.css`、`dist/art.js`のコードと照合した。自動テストとCloud Chromeの結果は実装担当の検証報告を反映し、スマホ実機・実タッチ・Safari・回転の未確認を分けて記録した。確認した試作の範囲を越えて、正式設定や全端末での動作保証として扱わない。
